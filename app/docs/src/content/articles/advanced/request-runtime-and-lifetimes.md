Fetch ハンドラーが `Response` を返しても、遅れて表示されるコンポーネントのレンダーが続いている場合があります。
Effront は、ハンドラーの呼び出し中だけでなく、レスポンス本文の処理が終わるまでリクエスト単位のリソースを保持します。

## Response の処理はハンドラーの後も続く {#response-lifetime}

ヘッダーを返した時点では、ストリーミングするレスポンスは完了していません。
ハンドラーの Promise が解決した後も、Suspense の内容や Flight データの生成にアプリケーションのサービスが必要になることがあります。
Effront は、本文が完了、失敗、キャンセルすると、リクエストの Scope を閉じて登録済みの解放処理を実行します。
本文がない場合やレスポンスの生成が失敗した場合は、ストリームを待たずに取得済みのリソースを解放します。

そのため、ハンドラーの呼び出しを囲む `finally` ブロックで接続を閉じると早すぎます。
後続のレンダーがまだその接続を使う可能性があるためです。

## アプリケーションのサービスはリクエストごとに構築される {#request-layer}

`EFFRONT.make({ routes, layer })` に渡す Layer は、`createFetchHandler` で作ったハンドラーをホストが再利用する場合も、リクエストごとに構築されます。
サーバー全体で共有するシングルトンではありません。
リクエスト固有の取得処理はこの Layer 内に置き、`Effect.acquireRelease` などの Scope に対応した操作で解放処理を登録します。
サービスの宣言、`Application.effront<Services>()`、Layer の登録方法は[サービスの設定例](/guide/effect#service)を参照してください。

Workers では、取得処理から [Workers のコンテキストアクセサー](/platforms/cloudflare#context)を使い、そのリクエストの `env`、execution context、元の `Request` を参照できます。
モジュールの読み込み時にリソースを開いても、このリクエスト単位の管理にはなりません。

## 遅れて始まるレンダーも同じサービスを使う {#render-scope}

Page、Layout、Component、Server Function は、処理中のリクエストのアプリケーションサービスを使います。
レスポンスのストリーミング中なら、遅れて始まるレンダーのために同じリソースを取得し直す必要はありません。
各リクエストは、それぞれのレンダー用 Scope を持ちます。
レンダーのストリームが中断されると、未完了のレンダー処理も中断されます。

レンダーはアプリケーションの Routes を通して実行する必要があります。
リクエスト runtime の外や、必要な Middleware が有効でない場所でレンダーすると、サービスを利用できるコンテキストは得られず、`TypeError` になります。

> [!WARNING]
> Workers のバインディングが自動的に Flight や HTML へシリアライズされることはありませんが、JSX、Client Component の props、Server Function の戻り値に含めた値は、ブラウザーへ届く可能性があります。
> これらの出力には、公開すると決めた値だけを含めてください。

## リクエスト所有とホスト所有のリソース {#resource-design}

Fetch ハンドラーをラップする場合は、本文のストリーミングとキャンセルを維持する必要があります。
独自に native HTTP と接続する場合も、本文の完了、失敗、キャンセルまでリクエストの Scope を保持する必要があります。
レスポンスの生成だけを `Effect.scoped` で囲むと、Scope を閉じるのが早すぎます。

アプリケーションの Layer の外から提供するホスト所有のサービスは、別の所有者が管理します。
`makeHttpEffect` はそれらのサービスへの参照を保持しますが、取得も寿命の延長も行いません。
所有者は、リクエストがサービスを使っている間、そのサービスを利用可能に保つ必要があります。
リクエストの解放処理がそのサービスを破棄することはありません。

レスポンス終了後も続ける処理には、ホストが対応するバックグラウンド処理の仕組みと、その処理が所有するリソースが必要です。
Promise を開始したり、リクエストのサービスを外側の変数に保存したりしても、そのサービスの寿命は延びません。
